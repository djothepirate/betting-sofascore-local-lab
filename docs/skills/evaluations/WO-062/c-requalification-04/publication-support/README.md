# Soutien à la publication C4

Ces octets sont des preuves de l'outil local de consolidation, distinctes des dix
contextes évalués. Ils ne sont pas des entrées des cas et n'étendent pas leur oracle.
La première revue FAIL est conservée ; la revue finale PASS porte sur le publieur
corrigé. Quatre tests synthétiques vérifient succès, échec du remplacement atomique,
manifeste incohérent et dérive d'entrée, sans modèle, Java ni harnais Windows.

La publication utilise un répertoire préparatoire complet et remplace la qualification
par une opération atomique par skill. Elle vérifie les octets et leur provenance avant
de publier. Une défaillance de remplacement ramène le nouveau dossier en préparation.
Cette garantie est par skill ; aucun engagement de transaction globale entre les deux
skills, d'arrêt brutal du processus ou d'échec du retour arrière n'est donné.

Les sources `.py.txt` sont conservées telles qu'exécutées depuis `.tmp` dans ce worktree.
Le publieur réutilise le validateur de run-02 ; ses appels locaux résolvent ces noms
d'origine. Cette copie documentaire n'est pas un nouvel installateur autonome.
