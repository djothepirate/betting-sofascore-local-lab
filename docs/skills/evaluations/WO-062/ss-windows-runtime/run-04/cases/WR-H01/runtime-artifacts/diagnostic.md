## Démonstration et limites

Start-Process recompose son ArgumentList en ligne native. Le chemin JAR non explicitement protégé devient plusieurs arguments lorsque ses répertoires ou son nom contiennent des espaces. Le helper ajoute les guillemets autour de la seule valeur canonique située après `-jar` ; l'enfant PowerShell contrôlé reçoit alors les six arguments exacts attendus. Les quatre refus effectivement exercés sont : chemin relatif, extension autre que `.jar`, guillemet et caractère de contrôle (LF). Le code du helper refuse également une valeur vide/blanche, les autres contrôles et les chemins non canoniques ; tous ces cas ne constituent pas des essais dynamiques supplémentaires dans cette exécution.

Cette preuve concerne cette frontière Windows/PowerShell 7 et ce chemin contrôlé. Aucun Java, JAR applicatif, PowerShell 5.1, signal CTRL_BREAK, Maven, Pester, CI, base ou réseau n'a été exécuté. Les flags JDK sont des arguments capturés, pas un comportement JVM testé. Le chemin sans espace est une valeur synthétique capturée : aucun fichier hors output n'est créé. Les captures JSON brutes, les PID internes et les durées individuelles ne sont pas conservés par le harnais original. La preuve persistante associe ses assertions de sortie à la sortie par handle du processus extérieur et au postflight indépendant du système de fichiers ; elle ne constitue pas un inventaire global des processus du poste.
